# Decision and Approval Schemas

All six records incorporate every common field under the normative Schema Incorporation Contract in `MATERIAL_OBJECT_INVARIANT.md`. Those fields must be physically present and validated in each concrete record; this reference is not a substitute field or default.

## Decision Gate

`decision_gate_id`, `gate_type`, `decision_class`, `gate_materiality`, `required_risk_refs`, `required_compliance_refs`, `required_jurisdiction_refs`, `required_policy_constraint_refs`, `required_contractual_constraint_refs`, `required_evidence_refs`, `required_analysis_professional_refs`, `required_challenge_refs`, `required_risk_QA_refs`, `required_conflict_refs`, `required_exception_refs`, `required_waiver_refs`, `required_dependency_refs`, `required_Human_Principal_refs`, `required_SOD_refs`, `required_input_category_counts`, `validated_empty_required_category_refs`, `approval_requirement_refs_and_versions`, `approval_requirement_count`, `gate_logic`, `gate_status`, `failed_condition_refs`, and `failure_route`. Every set is explicit; a legitimate empty set requires a category-specific entry in `validated_empty_required_category_refs`. Missing is not empty. Material gate logic is conjunctive and cannot use aggregate compensation.

## Decision Request

`decision_request_id`, `recommendation_ref`, `request_state`, `decision_requested`, `alternatives`, `no_action_alternative`, `rationale`, `benefit_refs`, `risk_and_residual_risk_refs`, `compliance_and_constraint_refs`, `uncertainties`, `limitations`, `dissent_refs`, `reversibility`, `consequence_refs`, `decision_gate_id_version`, `requested_decision_authority`, `requester_identity`, `requester_effective_actor_id`, `effective_actor_resolution_ref`, and `requested_at`. The request input categories reconcile to the Gate but cannot substitute for the Decision Record input snapshot.

## Decision Record

`decision_record_id`, `decision_request_id_version`, `decision_status`, `decision_category`, `decision_actor_identity_role`, `decision_actor_effective_id`, `effective_actor_resolution_ref`, `decision_authority_record_ref`, `decision_scope`, `decision_rationale`, `conditions`, `effective_at`, `expires_at_or_non_expiring_basis`, `input_snapshot_at`, `input_manifest_hash`, `input_set_status`, `evidence_input_refs_versions_hashes`, `analysis_professional_input_refs_versions_hashes`, `risk_input_refs_versions_hashes`, `compliance_input_refs_versions_hashes`, `jurisdiction_input_refs_versions_hashes`, `policy_constraint_refs_versions_hashes`, `contractual_constraint_refs_versions_hashes`, `conflict_record_refs_versions_hashes`, `approval_requirement_refs_versions_hashes`, `approval_record_refs_versions_hashes`, `exception_record_refs_versions_hashes`, `waiver_record_refs_versions_hashes`, `dependency_record_refs_versions_hashes`, `Human_Principal_refs_versions_hashes`, `input_category_counts`, `validated_empty_input_category_refs`, `input_reconciliation_status`, `input_reconciliation_ref`, `input_reconciled_at`, `required_approval_count`, `obtained_approval_refs`, `missing_approval_requirement_refs`, `rejected_approval_refs`, `expired_approval_refs`, `revoked_approval_refs`, `superseded_approval_refs`, `conditionally_valid_approval_refs`, `unsatisfied_approval_condition_refs`, `approval_chain_status`, `approval_chain_reconciliation_ref`, `approval_chain_reconciled_at`, `SOD_evaluation_ref`, `exception_waiver_evaluation_ref`, `conflict_evaluation_ref`, `jurisdiction_applicability_ref`, `compliance_validity_ref`, `risk_validity_ref`, `freshness_currentness_ref`, `gate_result_ref`, `dissent_refs`, `reversibility_plan_ref`, `revocation_triggers`, `execution_authority_ref` if separately required, and `Layer_11_workflow_ref`.

The typed input collections are the canonical exhaustive Decision Record snapshot, not summaries or indirect Gate/Request inheritance. Each entry contains exact object ID, record version, hash where applicable, client, legal entity, engagement, jurisdiction, source authority, lifecycle/currentness, and validation reference. Counts must equal unique membership. Every Gate/Request requirement must reconcile to exactly one applicable snapshot entry, and no undeclared entry may influence the decision. Missing, null, inferred, stale, superseded, revoked, wrong-version, unauthorized, cross-boundary, or unreconciled input blocks the Decision Record.

An empty category is valid only when structurally legitimate and named in `validated_empty_input_category_refs` with category, reason, authority, scope, and current validation. Omission, null, zero inferred from absence, or a blanket empty declaration is `INCOMPLETE_BLOCKED`.

`APPROVED` requires `input_set_status: VALIDATED_COMPLETE`, `input_reconciliation_status: RECONCILED_CURRENT`, `approval_chain_status: COMPLETE_CURRENT_SOD_VALID`, no missing/rejected/expired/revoked/superseded approval, every conditional approval condition satisfied, current conflict/SOD/jurisdiction/compliance/risk/exception/waiver/freshness validations, and every required Human Principal reference. Any unknown, missing, ambiguous, stale, expired, revoked, superseded, cross-boundary, or unreconciled state makes `APPROVED` invalid and `APPROVAL_BLOCKED`. A Decision Record does not execute or authorize an external action by itself.

## Approval Requirement

## Approval Record

`approval_record_id`, `approval_requirement_id_version`, `decision_request_id_version`, `approval_category`, `approver_identity`, `approver_role`, `approver_effective_actor_id`, `effective_actor_resolution_ref`, `approver_authority_record_ref`, `approval_scope`, `approval_disposition`, `conditions`, `condition_validation_refs`, `approved_at`, `expires_at`, `revocation_status`, `supersession_status`, `SOD_validation_ref`, `mandatory_SOD_rules_result`, `identity_authentication_ref`, and `consumed_or_reuse_status`. Approval is exact and non-reusable outside its object/version/scope/client/entity/engagement/jurisdiction/category. Unknown effective actor or incomplete SOD evaluation invalidates it.

## Escalation Record

`escalation_record_id`, `issue_type`, `materiality`, `affected_object_refs_versions`, `reason`, `containment`, `sender`, `recipient_canonical_authority`, `Human_Principal_required`, `requested_disposition`, `opened_at`, `due_at`, `status`, `resolution_ref`, and `closed_at`. Escalation is advisory routing, never approval or resolution.
