# Machine Identity and Automation Boundary

Service, system, model, agent, connector, and automation identities are non-human classes with exact owner, controller, purpose, permitted object/action scope, client/entity/engagement/jurisdiction boundaries, assurance reference, lifecycle, expiry, revocation, dependencies, and audit.

No machine identity may impersonate a human, become Human Principal, create or approve its own role/grant/delegation/elevation, expand scope, infer permission from task assignment, infer authority from data possession, or treat successful execution as authorization. Distinct model/agent labels under one controller resolve to the same effective actor for SOD.

A machine acting for another principal is a deputy, never an authority bridge. Authorization preserves the originating principal, every intermediary, and final executing machine and validates each separately. The permitted result is the least-privilege intersection of caller and every deputy; service privilege cannot cure an unauthorized caller, and caller authority cannot expand a service scope.

Layer 13 contains no machine identity instance, credential, runtime, agent, connector, tool, invocation, session, worker, or autonomous operation. It defines only future implementation constraints. Any machine operation requires separately certified implementation and the exact human/canonical authority references required by prior layers.
